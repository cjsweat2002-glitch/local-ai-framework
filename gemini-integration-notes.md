# Gemini Integration Notes

The official Gemini API documentation identifies `https://generativelanguage.googleapis.com` as the API host and uses the `x-goog-api-key` header for server-side API-key authentication. The current documentation recommends the Interactions API for new integrations and lists Gemini Flash-family models for low-latency generation. The existing connected Gemini integration identifies `gemini-2.5-flash` as an available model and confirms a server-side `GEMINI_API_KEY` credential.

For real-time output, the documented REST pattern is `POST /v1beta/interactions?alt=sse` with `stream: true`. Text is emitted in `step.delta` events whose delta type is `text`, enabling token-level forwarding to the existing browser chat transport. The connected key was validated against `gemini-3.6-flash` on the Interactions API; although `gemini-2.5-flash` appears in model discovery, the Interactions endpoint returned a model-unavailable error for that older identifier.

Source: https://ai.google.dev/gemini-api/docs (retrieved 2026-08-12).

## Dedicated developer workspace and synchronization boundary

The Gemini API supports server-side model interactions, SSE streaming, file utilities, and Python-only code execution. It can therefore power a first-class in-app Gemini workspace for direct code generation, design specifications, debugging, and web-development prompts. The existing `GEMINI_API_KEY` remains server-side; it must not be exposed in the browser. Source: https://ai.google.dev/api and https://ai.google.dev/gemini-api/docs/code-execution (retrieved 2026-08-12).

Consumer Gemini Gems are reusable custom experts in the Gemini application, but the Google AI Developers Forum states that the Gemini app does not expose an API or API access to Gems. The supported in-app alternative is a user-owned, versioned "Gem blueprint": store the Gem's instructions, files/context references, and preferred model settings in Autonomous AI Hub and apply them as a server-side system instruction to the Gemini API. Source: https://gemini.google/overview/gems/ and https://discuss.ai.google.dev/t/accessing-gemini-gems-through-api/40534 (retrieved 2026-08-12).

Google's supported programmatic notebook management applies to Gemini Notebook Enterprise, is currently Preview, and requires a licensed Google Cloud project plus Google authorization/IAM. It can create, retrieve, list, share, and delete enterprise notebooks. Connecting it requires the user's Google Cloud project number, location, and an OAuth or service-account access model with the relevant IAM role. Source: https://docs.cloud.google.com/gemini/enterprise/notebooklm-enterprise/docs/api-notebooks (retrieved 2026-08-12).

## Consumer Gemini app and website source editing

Google's consumer Gemini web app can connect to GitHub and import a repository for codebase understanding, explanations, suggestions, and debugging. That import is a static snapshot: later repository changes are not synchronized into the Gemini chat. Google explicitly states that the Gemini app GitHub connection cannot retrieve commit history, pull requests, or other repository metadata and cannot write to a code repository. It therefore cannot directly edit or deploy the Autonomous AI Hub from the Gemini app. Source: https://support.google.com/gemini/answer/16176929 (retrieved 2026-08-13).

The supported edit-capable route is repository mediated: use the Gemini CLI GitHub Action or Gemini Code Assist inside the GitHub repository. Google's GitHub Action supports on-demand assistance in issues and pull requests through `@gemini-cli`, code analysis and modification, and pull-request review. It requires a repository-level Google authentication choice (typically a `GEMINI_API_KEY` stored in GitHub Actions secrets or Workload Identity Federation), and its own GitHub token/app permission. The existing website server secret must remain only in the website environment and cannot be copied to GitHub automatically. Sources: https://github.com/marketplace/actions/run-gemini-cli and https://docs.cloud.google.com/gemini/docs/code-review/review-repo-code (retrieved 2026-08-13).

The user installed the official Google Integrations GitHub App on August 13, 2026. Its installation page confirms that this particular app has **read** access to code and metadata and states that it imports selected GitHub repositories into Gemini prompts for code analysis. It does not grant write access, so it cannot edit website source or trigger a deployment. The installation currently shows all-repository access selected and should be narrowed to `cjsweat2002-glitch/local-ai-framework` if the user continues using it.

The Google Integrations installation was then narrowed and saved to the sole repository `cjsweat2002-glitch/local-ai-framework`. It remains intentionally read-only, enabling codebase import and analysis in Gemini Apps while preventing direct source or production changes from the consumer Gemini interface.

The user then stored a separate Gemini credential as the encrypted GitHub Actions repository secret `GEMINI_API`; its value was not read back, copied into the website, or committed to source. The repository now contains a guarded Gemini CLI Action workflow. A trusted owner starts a plan by commenting `@gemini-cli <request>` on a GitHub issue or pull request. The workflow can only inspect source and publish a file-specific plan. A code-change run requires the same owner to comment `@gemini-cli /approve`, then can create a new branch and pull request only. It excludes automatic triggers, direct writes to `master`, merging, deployments, workflow edits, secrets, and repository settings. The GitHub Google Integrations app remains a separate, repository-scoped read-only code-import connection.
